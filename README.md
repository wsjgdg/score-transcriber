# 音视频转乐谱 · Score Transcriber

输入一段**音频或视频**，自动识别音高与节奏，输出五线谱、钢琴卷帘图、简谱，以及可下载的 MIDI / MusicXML。

## 在线体验
部署链接（沙箱托管，临时可用）：`https://a0e04ccda5baf1d36.gz4.agentos-app.net`

打开后点「点击选择音频 / 视频文件」→ 选 ≤1 分钟、<30MB 的片段 → 「开始转谱」，约 10–60 秒出结果。

## 产出内容
- **五线谱**（LilyPond 渲染 PNG，每个音符上方小字标注其模型响应强度百分比）
- **钢琴卷帘图**（PNG，多声部、颜色=力度，并在每个音符方块上标注**模型响应强度百分比**，可单独下载）
- **简谱**（数字谱，和弦用 `+` 连接，括号里是时值/拍，如 `1+3+5(4)`；支持选调到目标调，表头改为 `1=X`）
- **MIDI** / **MusicXML**（可导入 MuseScore / Sibelius / Finale 等；MusicXML 在每个音符下方以歌词形式标注响应强度百分比）
- **音频播放**：原音频与「识别出的钢琴谱」均可在页面内直接播放。钢琴谱优先用 **fluidsynth + 真实钢琴音源**（soundfont）渲染，环境缺失时自动回退到纯 numpy 基础合成；两个播放器并排展示，各带播放/暂停按钮与可拖动进度条，并提供一个「对比播放」按钮可同时播放原音频与识别钢琴谱。
- **响应强度**：结果区显示整体响应强度百分比与提示，辅助判断是否需人工核对（注意：该数值代表模型对音符的激活/响应强度，并非转录准确度的保证）
- **历史记录**：每次成功转谱都会自动保存到磁盘（`history.json`），**重启/重新发布后仍在**；页面「历史记录」卡片支持按文件名实时筛选，点「查看」会**跳转到独立页面**（`/view.html?id=…`）回看乐谱、播放原音频/钢琴谱并重新下载，不会在当前页展开；每条记录右侧有「删除」按钮可**单条删除**（同时回收其输出目录，释放空间）。最多保留最近 50 条，更早的记录及其输出文件会被自动回收以节省空间。

## 技术栈
- 音视频解析：**ffmpeg**
- 多音转录（Automatic Music Transcription）：**Spotify basic-pitch**（TFCN 模型）
- 五线谱渲染：**LilyPond**
- MusicXML / 和弦建模：**music21**
- 后端：**FastAPI + uvicorn**；前端：原生 HTML / JS

## 识谱原理
本工具做的是 **AMT（自动音乐转录）**，输入是声音波形、输出是音符序列，与"拍照识别乐谱"完全不同。管线：

1. **音频 → 谱图**：对波形做短时傅里叶变换（STFT），得到时间-频率二维能量图。
2. **模型推理**：basic-pitch 的 TFCN 网络同时输出三张预测图——**音高轮廓**（每时刻每个 MIDI 音高是否有音）、**起音 onset**、**偏移 offset**。
3. **后处理**：onset 定位音符起点，音高轮廓跟踪持续段，按帧阈值（onset 0.5 / frame 0.3）滤噪、过滤过短音符，合成 `(起始, 结束, 音高, 力度/响应强度)` 列表。
4. **量化成谱**：`transcriber.py` 按你填的 BPM/拍号把音符对齐到节拍网格，分组为和弦事件，再渲染五线谱 / 简谱 / MIDI / MusicXML。

**复调/和弦天然支持**（模型多音输出），钢琴卷帘里的多层方块、简谱里的 `+` 连接即为证据。

## 准确度（实话）
basic-pitch 官方评测大致水平：
- **音符级 F1**（音高+起止都对）约 **0.8**；**起音 F1** 更高，约 **0.85–0.9**——"什么时候响"判得很准，难点在**时值**与**重叠音分离**。
- **音高识别本身很准**，主要误差来自时值与密集和声。

真实体感的三点局限：
1. **强伴奏大幅拉低准确度**：人声/主旋律清晰的独奏最好；流行歌带鼓+贝斯+和声会误捡、漏弱音。
2. **时值不准是常态**：模型给连续时间，再用 BPM 量化；BPM 填错整张谱节奏就歪。
3. **极端音区/滑音/装饰音**识别差（长持续音、颤音、推弦等）。

**结论**：旋律轮廓与和弦构成能抓个七八成，适合"听个大概、辅助记谱"，不能直接当出版谱。建议用 MIDI/MusicXML 下载到 MuseScore 人工校对。

## 响应强度与降噪
- **响应强度（原称"置信度"）**：取自模型对每个音符给出的激活强度均值（即 basic-pitch 的 velocity 字段）。它反映模型"听到了这个音"的把握程度，**并不等同于转录准确度**——强伴奏/噪声也可能产生高响应。≥75% 代表模型激活充分；55–75% 建议对照钢琴卷帘图核对；<55% 可能伴奏强/录音嘈杂，需谨慎对待。
- **钢琴卷帘标注**：每个音符方块上直接印出该音符的响应强度百分比（如 `90%`），颜色越亮代表模型激活越强，一眼就能看出哪些音是"猜测"。该 PNG 提供独立下载按钮。
- **五线谱 / MusicXML 同样标注响应强度**：五线谱在每个音符上方以小字标出百分比；MusicXML 则在每个音符下方以歌词形式标出百分比，导入 MuseScore / Sibelius 后一眼可辨哪些音是"猜测"，方便人工校对。
- **降噪阈值（前端可调）**：上传页提供 0–0.9 的滑块，过滤掉响应强度低于该阈值的弱音符，**默认 0.5**（相当于旧版"降噪模式"勾选）。
  - 设为 **0** = 不降噪，保留全部识别结果；
  - 设得越高越严格，能显著减少强伴奏/噪声造成的误捡，但代价是可能丢一些本就微弱的弱音。
  - 不确定就保持 0.5；若结果仍嘈杂可逐步往右拉，若丢音明显则往左收或归零对比。

## 识别准确度优化（进阶选项）

上传页「进阶优化」区提供开关与下拉，默认已按最佳实践开启最核心的「分离伴奏」「人声单旋律模式」「纯净后处理」：

- **八度偏移（下拉）**：basic-pitch 对泛音丰富的乐器/人声、低音源常出现系统性高/低八度误判。若谱面整体比实际高/低了整数个八度，用此下拉整体上下移 ±1/±2 八度即可，比逐音改更省事。后端对 `note_list` 整体 `transpose_note_list(notes, 12 * shift)`，与选调移调叠加。
- **自动八度校正（F0 重锚定，默认开启）**：多数情况无需手动选八度偏移——工具会用 pYIN 从原音频估出**真实基频轨迹**，再把 basic-pitch 误判成高八度的音符（音名相同、高 1~2 个八度）自动拉回真音高。只在「谐波/根音音名一致且确实高了一个八度以上」时才生效，复调/音名不符时不误伤。关闭「纯净后处理」时仍有效；若你确认无系统性偏差可取消勾选。
- **分离伴奏（Demucs）**：转谱前先用 Demucs(htdemucs) 把音轨分离，仅用选定的声部（人声 / 钢琴(other) / 自动）去转录。对带鼓、贝斯、和声的流行歌/视频能大幅减少误捡，是准确率提升最大的一步。前端会探测运行环境：装了 demucs 则默认勾选；**免费托管环境未预装时会自动取消并提示，转录回退原音频**。自托管（Dockerfile 已含 demucs）或自有 GPU 服务器可启用。
- **仅保留强响应音符（≥75%）**：开启后只保留模型响应强的音符再生成乐谱，得到干净谱；若过滤后无剩余（整段都偏低），自动回退完整结果以免空谱。
- **自动估计 BPM**：用 librosa 节拍跟踪自动估速，忽略手填 BPM；估不出节拍时回退手填/默认值。
- **智能降噪**：按音频信噪比自适应调整 basic-pitch 的 frame 阈值（越噪越严），无需手动设降噪滑块。
- **模型后端**：默认 basic-pitch（快）；可选 MT3（复调/多乐器、带力度，上限最高）。MT3 依赖极重，仅在有 GPU 的自托管环境安装后可切换，免费托管环境会返回友好提示。

响应强度展示也升级为多指标：**均值 / 中位数 / 强响应占比**，并在结果区标出本次启用的优化项，便于判断结果可信度。

## 人声歌词（把歌词打到五线谱每行下方）
核心识别是 **AMT（只识别音高/节奏），不识别歌词文字**；所谓「识别的人声」默认指分离出来的人声音**轨**，不是识别出的歌词。把歌词放到五线谱下方有两种方式：

- **手动填词（默认开箱即用，免费托管也可用）**：在「歌词」文本框粘贴歌词。中文按字、英文按词自动切分，并按音符顺序一对一地对齐到每个音符；词少于音符时多余音符留空，词多于音符时多余词被忽略。歌词会同时渲染到 **LilyPond 五线谱（`\addlyrics`，谱面下方）** 与 **MusicXML（verse 1 歌词 + verse 2 响应强度%，导入 MuseScore/Sibelius 可见）**。
- **自动识别（Whisper ASR，需自托管 GPU）**：勾选「自动识别人声歌词」后，工具用 Whisper 对「人声干声」做词级时间戳识别，再按时间把词对齐到音符。Whisper 模型很重，免费托管环境未预装且跑不动，会返回友好提示；在自有 GPU 服务器上安装 `faster-whisper`（或 `whisper`）后该选项自动启用。

> 对齐为「一对一 / 按时间最近」的轻量方案，适合主旋律与歌词基本同步的歌曲。若某段是长音拖腔（一个音跨多字），仍需手动微调歌词文本框。

## 识谱成曲（图片识别 OMR）

除"听声音转谱"外，本工具也能**识别乐谱图片**生成可播放/可下载的谱。点击顶部「🎼 音视频转乐谱」标题旁的 ▾，在弹出列表里切到「📷 识谱成曲」，即可上传乐谱图片，支持两种记谱法：

- **简谱（numbered notation）**：本地 OCR（PaddleOCR 或 Tesseract）识别数字与装饰符号，纯启发式解析，无需额外重型引擎。
- **五线谱（staff）**：接入开源 OMR 引擎 **Audiveris**（Java）把图片转成 MusicXML，再用 music21 解析；环境未装 Audiveris 时接口会返回友好提示与安装指引，而非静默失败。

### 使用步骤
1. 顶部标题旁点 ▾ → 选「📷 识谱成曲」。
2. 选图片（支持 `png/jpg/jpeg/webp/bmp`，建议清晰、横排、印刷体）。
3. 选记谱法（简谱 / 五线谱），填 BPM、拍号、选调（与转谱一致）。
4. 点「开始识谱」，约数秒出结果。

### 产出
与"音视频转乐谱"**完全一致**的产出管线（复用 `transcriber.build_outputs`）：五线谱 PNG、钢琴卷帘、简谱、MIDI、MusicXML、以及**合成试听**（由谱面用 fluidsynth/基础合成出声）。注意 OMR 模式**没有原音频**，试听播放的是识别出的谱面本身。

### 引擎依赖
- **简谱 OCR**：二选一 —— `pip install paddleocr`（中文印刷体更准）或 `pip install pytesseract`（另需系统装 `tesseract-ocr`）。两者皆无则报 `BackendUnavailable`。
- **五线谱 OMR**：需自行安装 **Audiveris**（Java 11+），把 `audiveris`/`Audiveris` 可执行文件加入 PATH，或把 `audiveris.jar` 放到 `/opt/audiveris`、`~/audiveris`、`C:\Program Files\Audiveris` 等目录。运行时自动探测；缺失则提示安装。解析 MusicXML 复用上方已列出的 `music21`。

### 局限
OMR 为启发式实现，**针对印刷清晰、排版规整**的乐谱效果最好；手写、花哨字体、竖排或带复杂装饰的谱可能识别不准。简谱解析核心 `parse_jianpu_glyphs` 是纯函数（八度点/减时线/附点规则见其 docstring），可独立单测（`test_omr_jianpu.py`）。识别结果建议导出到 MuseScore 人工校对。

## 环境变量（.env）
项目根目录可放 `.env`（已被 .gitignore 忽略，勿提交），格式参考 `.env.example`。当前读取的变量：
- `PORT`：后端监听端口（run.py 读取，默认 8000）。
- `GITHUB_TOKEN`：仅用于本地 git 推送 / 调试 CI，不进入应用运行时；含密钥，务必只留在本地 `.env`。

**本地推送**：`GITHUB_TOKEN` 填好后，运行 `./scripts/push.sh`（或 `make push`）会从 `.env` 读取 token 并推送到当前分支，避免密钥出现在命令行参数或聊天里。

## 说明与局限
- 旋律型内容识别最佳；强伴奏 / 嘈杂录音会干扰，建议选人声或主旋律清晰的片段，必要时开降噪模式。
- BPM / 拍号用于节奏量化，填错只是时值不准，可换值重传。
- 五线谱在和弦过多时截断到前 600 个（钢琴卷帘与 MIDI 为完整内容，不截断）。
- 免费托管环境对单次请求有超时限制，长文件可能失败——非本机算力问题。
